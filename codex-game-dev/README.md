# Codex 游戏开发能力库

这是面向后续所有游戏项目的共享能力库。它把“做出能运行的游戏”提升为“完成度可验收、资产可复用、迭代可持续”的开发流程。

## 解决的四类问题

1. **能运行，但视觉不够好**：用视觉方向、资产规格、构图与统一性检查，把默认原型提升到可展示的画面。
2. **功能完整，但不好玩**：用核心循环、即时反馈、节奏、风险回报和可读性检查，验证玩家是否真的愿意继续玩。
3. **内容做了很多，但体验不完整**：用垂直切片、内容层级和完成度清单，确保关键路径有开场、目标、反馈、变化和收束。
4. **能交付，但难以稳定迭代**：用模块边界、数据驱动、回归检查和性能预算，降低改一处坏多处的风险。

## 目录

- `SKILL.md)：Codex 在游戏项目中应遵循的主工作指令。
- `docs/quality-gates.md`：四类质量闸门与最低验收标准。
- `docs/workflow.md`：从想法到可玩的垂直切片，再到交付的工作流。
- `templates/game-brief.md`：项目启动简报。
- `templates/visual-spec.md`：视觉方向与资产规格。
- `templates/playtest-report.md`：试玩记录与问题排序。

## 使用方式

把本目录复制或链接到目标游戏项目的 Codex skills 目录；开始新项目时先填写 `game-brief.md`，再按 `SKILL.md` 推进。每个阶段都要留下可运行的结果和一份验收记录。

## 原则

- 先做一条完整可玩的核心路径，再扩展内容。
- 视觉问题优先用明确规格和资产清单解决，不靠临时堆提示词。
- 每个系统都要能说明它为玩家体验带来什么。
- 每次改动都要能快速验证：能运行、看得懂、玩得下去、改得动。
