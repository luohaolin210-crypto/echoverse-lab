# 四类质量闸门

## 1. 视觉完成度

### 最低标准

- 有一句话视觉方向：题材、情绪、材质、色彩和参考尺度明确。
- 主界面、游戏场景、角色或关键道具拥有稳定的层级关系。
- 玩家焦点明确；背景不会与交互物抢注意力。
- 关键资产有统一的比例、光照、边缘处理和命名。
- UI、文字、图标和状态变化在目标分辨率下可读。

### 检查问题

- 截图缩小后，玩家还能看出当前目标吗？
- 关键状态是否不依赖颜色单独表达？
- 同一类资产是否像来自同一个世界？
- 是否存在明显的默认素材、临时占位或风格冲突？

## 2. 可玩性与反馈

### 最低标准

- 玩家能在第一次尝试中完成核心动作。
- 输入到结果的反馈足够快，且至少有视觉或声音确认。
- 成功、失败、受伤、获得奖励和目标变化都能被辨认。
- 核心循环至少能连续完成三次，并且每次有可感知的变化。
- 难度来自决策或风险，而不是来自不清楚的规则。

### 检查问题

- 玩家下一步要做什么是否明显？
- 玩家为什么失败是否能理解？
- 每个系统是否服务于一个明确的玩家选择？
- 操作、动画、音效、粒子和镜头是否在强调同一个结果？

## 3. 内容与体验完整度

### 最低标准

- 有进入、目标、行动、变化、结果和再次行动的闭环。
- 关键路径不需要开发者解释才能完成。
- 内容有节奏：安全、挑战、变化、奖励或收束至少出现一次。
- 重要系统至少有一个真实使用场景，而不是只有按钮或接口。
- 试玩者能用自己的话复述“我在做什么”。

### 检查问题

- 开始后 30 秒内是否出现有意义的选择？
- 中途是否出现新的信息、风险或策略变化？
- 结束时玩家是否知道自己完成了什么？
- 是否有被实现但没有进入体验的孤立功能？

## 4. 稳定性与迭代性

### 最低标准

- 有明确的启动方式和目标平台。
- 关键玩法状态可被稳定复现。
- 规则、数值和内容尽量数据驱动，不散落在事件处理代码里。
- 核心路径改动后有最小回归检查。
- 有基础性能预算：帧率、加载时间、资源体积或对象数量至少明确一项。

### 检查问题

- 新增一个敌人、关卡或道具是否必须复制大段代码？
- 出错时能否定位到输入、状态、资源或渲染哪一层？
- 重新启动后是否能回到可验证的初始状态？
- 为了修一个视觉问题，是否意外改变了玩法规则？

## 交付判定

四类闸门都达到“通过”或明确记录为“有意延期”，才算完成一个可交付切片。任何“暂缓”都必须写出原因、影响和补齐时机。
